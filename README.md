# VibeData AI 공용 이상 탐지 엔진 (Python) · v1.1

## v1.1에서 바뀐 것 (2026-11-10)
- **두 가지 모드**: 시간 열이 있으면 `시계열 모드`(센서처럼 순서가 있는 데이터, 이벤트로 묶음), 없으면 `표 모드`(보험 계약·건강검진처럼 한 행이 한 사람·한 건, 이상치 행만 찾고 묶지 않음). 시간 열은 없지만 순서가 의미 있으면 `mode="timeseries"`로 지정.
- **범주형 숫자 열 제외**: 값이 5가지 이하인 정수 열(성별 1/2, 여부 0/1, 등급 1~5)은 범주로 보고 자동 선택에서 뺌.
  - 그중 0부터 이어지고 큰 값일수록 드문 열(사고 건수 0~4, 자녀 수)은 `횟수`로 표시. 자동 선택에서는 똑같이 빠짐.
- **절반 넘게 같은 값인 열**(사고 건수처럼 0이 대부분)은 직접 골라 넣어도 통계적 이상치로 보지 않고 기준 규칙만 적용. 퍼짐이 0이라 1건만 있어도 이상치가 되기 때문. 이런 열은 `rules`(예: 사고 3건 이상)나 분포표로 보세요.
- **표 모드는 숫자 열을 최대 12개까지 자동 선택** (시계열 모드는 원본과 같게 6개).
- **표 모드의 ID 열 판별**: 행 순서가 섞여 있어도, 값이 모두 다른 정수 열 중 이름에 id·번호·코드가 있거나 값이 거의 연속인 열은 `번호·순번`으로 보고 분석에서 뺌.
- **표 모드는 중복 행을 빼지 않음**: 같은 값의 사람이 둘일 수 있어서.
- **치우친 열은 로그 척도**: 보험금·간수치처럼 한쪽으로 길게 늘어진(왜도 > 1) 0 이상 열은 로그로 바꿔서 봄. 정상 고액 건을 무더기로 이상치로 잡지 않게. 0 이상 열의 정상범위는 0 밑으로 내려가지 않음.
- **표 모드 다변량 기준 강화**: 값 하나하나는 범위 안인데 조합만 드문 행은 점수 1.5 이상일 때만 표시.
- 새 함수: `check_table(out)` 데이터 점검 표, `report_text(out)` 모드에 맞는 기본 리포트.

데모 사이트의 JS 엔진을 Python으로 옮긴 것입니다. 계산만 하고 화면은 각자 페이지에서 만듭니다.

## 페이지에서 쓰는 법
```python
from engine import load_csv, run_engine, check_table, events_table, report_text
table = load_csv(file)                 # 업로드한 CSV (UTF-8·CP949 자동). DataFrame을 바로 넣어도 됨
out = run_engine(table)                # 이상 탐지 (모드 자동: 시간 열 있으면 시계열, 없으면 표)
st.dataframe(check_table(out))         # 데이터 점검: 열마다 역할·빈칸·고유값 수
st.dataframe(events_table(out))        # 시계열 모드 = 이벤트 / 표 모드 = 확인이 필요한 행
st.markdown(report_text(out))          # 기본 리포트
```
- 모드 강제: `run_engine(table, mode="table")` 또는 `mode="timeseries"`. 시간 열 대신 초·순번 숫자만 있는 센서 데이터는 자동이면 표 모드가 되므로 `mode="timeseries"`를 꼭 지정
- 지금 어떤 모드로 돌았는지: `out["mode"]`, 자동으로 고른 열: `out["columns"]`
- 열을 직접 고르기: `run_engine(table, columns=["노즐 온도", "진동"])`
- 민감도: `k=1.0`이 기본. 크면 덜 민감, 작으면 더 민감
- 내 분야 기준 규칙 넣기:
  `rules=[{"id": "r1", "col": "공복혈당", "op": ">=", "value": 126, "durationMin": 0, "label": "공복혈당 126 이상", "source": "진료지침"}]`
- 행마다 점수(그래프용): `scores_table(out)` · AI에게 보낼 요약: `out["summary"]`

## 페이지별 추천 사용법
| 페이지 | 모드 | 본문에 쓸 것 |
|---|---|---|
| 제조 PHM | 시계열 | 이벤트(`events_table`) |
| 엔진 실험실 | 시계열 | 이벤트, 이상 주입 실험 |
| 보험 계리 | 표 | 데이터 점검(`check_table`), 필요하면 이상치 행(입력 오류·극단 청구 확인용) |
| 헬스케어 | 표 | 데이터 점검, 기준 규칙 해당 비율, 이상치 행(입력 오류 확인용) |

표 모드에서 표시된 행은 '틀린 값'이 아니라 '확인이 필요한 값'입니다. 입력 실수일 수도, 실제로 드문 사람(건)일 수도 있습니다.
보험·헬스케어 본문의 결론은 각자 분야의 기준(요율·진료지침 등)으로 내리고, 엔진 결과는 데이터 품질 점검 보조로 쓰는 것을 권합니다.

## 표 모드가 판정하는 방식
- 열마다 중앙값과 MAD로 robust Z를 구해서 |Z| ≥ 4(민감도 k=1 기준)면 그 열의 이상치
- 여러 열의 조합이 드문지 다변량 점수로 보되, 값 하나하나가 모두 평범한 행만으로 기준을 만듦
- 기준 규칙(`rules`)을 넣으면 해당 행은 무조건 표시. 행 순서는 결과에 영향 없음

## 엔진이 판정하는 방식 (시계열 모드)
| 방법 | 보는 것 | 반응하는 예 |
|---|---|---|
| 튀는 값 | 주변 값의 중앙값과의 차이 | 순간적으로 확 튄 값 |
| 관리도(EWMA) | 기준선에서 서서히 멀어지는지 | 마모로 천천히 오르는 값 |
| 변동성 | 최근 흔들림이 평소의 몇 배인지 | 센서 고장으로 들쭉날쭉 |
| 다변량 | 변수끼리 관계가 평소와 같은지 | 하나씩은 정상인데 조합이 이상 |

- **기준 구간:** 데이터 앞쪽 30%(최소 30행)를 정상으로 보고 기준선을 만듭니다. 앞부분이 이미 이상이면 결과를 믿기 어렵습니다.
- **판정:** 2가지 이상이 동의하거나, 한 방법이 아주 강하게 반응하거나, 기준 규칙을 어기면 이상입니다.
- **이벤트:** 이어진 이상 행을 묶고 유형(튀는 값·수준 이동·서서히 변화·변동성 증가·관계 이상)과 등급(위험·경고·주의)을 붙입니다.
- **알아둘 점:** 완전히 같은 행은 중복으로 보고 뺍니다. 시간 열이 있으면 시간순으로 정렬합니다.
- **센서 원자료에 바로 쓰면 민감:** 기준 구간을 데이터 앞쪽에서 자동으로 잡기 때문에, 정상 운전 데이터에서도 '경고' 이벤트가 여럿 나올 수 있습니다. 판정용으로는 정상 운전 기준선을 따로 잡는 페이지 자체 로직을 쓰고, 엔진은 비교·탐색용으로 쓰세요.
